## Dependency notes

- 003 must not rely on 002's leader fix; together they close the two-tails-during-failover window (002: flag goes false as soon as the lock session dies; 003: rewind/wipe are fenced by expected tip hash).

## Not planned (real, but need a product decision or are larger)

- **Backfill admission/credit budget** for arbitrary addresses (random-address flood can burn the 80M-credit month in ~2 days; zero address is the worst single case). Needs a budget policy + denylist decision; also implies tracking only after admission (touches the handoff invariant).
- **Tracked set grows forever** (no untrack/TTL); same decision as above.
- **Per-process backfill dedupe** across replicas (duplicate full scans; chunk-overlap 500). Needs a per-account lease.
- **Follower catch-up memory** (500-block unfiltered responses ≈ 225 MB JSON parse). Mitigation is a config default change (e.g. 100 blocks) at ~no credit cost — trivial, decide with the cost model.
- **Pagination / response caps** for heavy accounts (API shape change).
- **Balance sweep scales with every token ever touched** (spam tokens); needs touched-pairs refresh.
- **Postgres concurrency integration tests** (real multi-connection handoff, `pgLeaderLock`) — docker-compose suite.

## Findings considered and rejected

- Reorg reaching cursor+1 wipes instead of rewinding to the cursor: the tail normally spans 64–95 blocks above finalized, so such a reorg would revert a finalized block; covered by an existing by-design test.
- Lagging endpoint silently truncating a finalized `eth_getLogs` range: finalized blocks are 64+ behind the tip; a node that far behind is implausible on the provider; out-of-range validation (002) covers the cheap part.
- `/health` exposes error strings and endpoint origins: keys are redacted (tested); PoC with no auth by design.
- Strict-decode skips of non-standard Transfer logs: deliberate (non-32-byte ERC-20 data etc.).
